# Live copy editor (dev tool, #59)

For the product designer: change UI copy in the running dev app and have it land on `main` with its tests, without a terminal and without a pull request in between (#340).

**Use it.** `npm run dev`, open the board, press Cmd/Ctrl+K and run **Edit UI copy: text selection mode**. Alt+Shift+K turns the mode on and off on every page, also where there is no command bar (the welcome screen, `/ui`): a click in the mode picks text instead of acting, so to reach a setup step turn it off, click through, and turn it on again. Text that comes from an i18n key gets an outline on hover; click it (or press Alt+K and search every key in both languages) to open the editor. Write one language; the other is translated by the agent when you press **Translate** in the Publish view, or write it yourself (**Write EN myself**). The app shows saved edits at once and keeps them over a page reload. **Publish to main** runs the job described under "How a publish lands" (minutes, the Publish view shows the stage); the edits stay visible until you **Clear published**. Leave with Esc, Alt+Shift+K or the bar's Leave.

**Needs** a local, set up checkout: `git` with push rights to `origin` (and to `main`: the ruleset blocks only force pushes and deletion), `gh` logged in (without it the branch is pushed and the PR is left to you), the `claude` CLI logged in for the translation (`KANDO_COPY_AGENT_CMD` names another command), `node_modules` installed (the checks and the build run from it) and the Playwright Chromium of the repo.

**Rules it enforces.** Only existing keys of `i18n/locales/de.json` and `en.json` change. A string that uses an avoid form of a `decided` term in `docs/copy/terms.json` cannot be saved; a `proposed` one warns. `{placeholders}` and plural branches must match in both languages. Task titles and notes (`data-private`) are data, not copy, and are never offered.

**How it is kept out of production.** `__COPY_EDITOR__` (`nuxt.config.ts`) is true in `nuxt dev` and in builds with `KANDO_COPY_EDITOR=1` (only `scripts/e2e-server.mjs` sets it, so the E2E specs can drive the tool); every other build drops `dev-tools/copy-editor/` and the recorder plugin. The two routes (`POST /api/dev/copy/translate`, `/publish`, `server/copy-editor/`) are registered through `nitro.handlers` in `nuxt dev` only, never in a build. They answer only on localhost with a JSON body and the `x-kando-copy-editor` header. `tests/config/copy-editor-build-output.test.ts` proves a flag-free build has none of it (`npm run generate`, then that test; CI does both).

**On Vercel (#246).** The dev instance is the Vercel Preview of the `dev` branch: its build carries `/ui` and this editor (`isDevInstance` in `lib/devPages.ts`: `VERCEL_ENV=preview` and `VERCEL_GIT_COMMIT_REF=dev`, or `KANDO_DEV_INSTANCE=1`). Update it with `npm run deploy:dev` (fast-forwards `origin/dev` to `origin/main`). Selecting and editing work there, edits stay in the browser; **Translate** and **Publish to main** do not (their routes exist only in `nuxt dev`). Production and `proto/*` previews stay free of it. The instance is as private as the preview's Vercel Authentication, which must stay on.

**How a publish lands (#340).** `POST /api/dev/copy/publish` starts one background job and answers at once; the view polls `POST /api/dev/copy/publish-status` (stage, notes, result). It never touches your checkout: it fetches `origin/main` into a temporary detached worktree (the packages are linked, `.nuxt` is the worktree's own, never the dev server's), writes the two locale files and then, in order:

1. `npx vitest run tests/i18n` (the existing `i18n:check`).
2. **Rewrite** (`follow.ts`): the old value of every changed key becomes the new one where it stands as a whole string literal in `tests/**/*.ts` or as a whole name or scalar in an ARIA snapshot (`tests/e2e/snapshots/**/*.aria.yml`). Values under 3 characters, values another key shares, regexes and fragments are not rewritten blindly; the editor's own tests (`tests/server/copy-editor`, `tests/lib/copy-editor`) and `tests/fixtures` are skipped.
3. **Verify** (`verify.ts`): `npm run verify` (what the pre-push hook runs), then exactly the specs `scripts/e2e-gate.mjs` selects for the diff (quality mode, so the label match finds the specs that quote the old copy) plus `visual-regression` and `state-structure`, against a production build on a free port (never the dev server).
4. **Baselines**: visual and ARIA tests that fail only because the copy moved are re-recorded for those tests alone (`--update-snapshots=changed`); a run that changes anything else, or more than 30 PNGs, is drift and stops here.
5. **Repair** (`repair.ts`): what is still red goes to the `claude` CLI (`KANDO_COPY_AGENT_CMD`) with file tools only, in the throwaway worktree, at most 2 rounds. It may change `tests/` only (anything else is reverted and stops the publish) and answers `needs-owner` when an assertion's meaning conflicts with the new copy (for example a test that says a word is absent). Its edits are listed in the commit body: read them.
6. **Push** one commit to `main`, `git push --no-verify origin HEAD:main` (never forced; the checks above are the ones the hook and the merge gate would run).

When any step fails, or `main` moved meanwhile (no automatic rebase: the verified tree is the one that lands), the same commit goes to a `copy/<date>-<key>` branch with a PR whose body names the failed step and its output, and the view says so. A failure before the rewrite (validation, fetch, worktree, prepare, i18n check) pushes nothing and keeps the edits. The worktree, the scratch directory and the local branch are removed on every path; scratch directories of a job that died with the dev server are swept at the next start.

**How a text finds its key.** `plugins/copy-editor-recorder.client.ts` hooks vue-i18n's `postTranslation` and remembers which key rendered which string, so interpolated and plural strings map exactly (a reverse lookup in the locale files cannot). Two keys with the same text are offered as a choice.
