# ADR 022: Apple Reminders access: EventKit through objc2 in the app crate, full access only, date-only writes

## Status

Accepted (epic #481, slice 1: #550; decisions E1 and E5 of the epic, D1 of #481 for the entitlement and the usage string). The ADR number was taken as the next free one on `main` and may be renumbered at merge.

## Context

The desktop app is meant to let users plan their day from Apple Reminders (epic #481). The web view cannot reach EventKit, so the access has to come from the native side. This slice builds only that bridge; no UI and no adapter call it yet (slices 2 to 4 of #481 do).

## Decision

- **Rust commands in the app crate on `objc2-event-kit` 0.3** (`src-tauri/src/reminders.rs`), the same toolchain as `capture.rs` and `data_file.rs` (`objc2` 0.6, `block2` 0.6 were already in the tree). Rejected: a Swift helper binary or Tauri plugin (a second toolchain and a second signed binary for a handful of calls), AppleScript through `osascript` (slow, the Automation prompt instead of the Reminders prompt, no due-date components).
- **Commands:** `reminders_access_status`, `reminders_request_access`, `reminders_lists`, `reminders_fetch`, `reminders_set_due`, `reminders_set_completed`, `reminders_open_settings`; the wrapper is `lib/reminders.ts`, the E2E mirror the `reminders_*` branches of `tests/e2e/helpers/tauriStub.ts`. App commands need no capability entry (`secrets::*` proves it); only the System Settings URL joins the scope of `opener:allow-open-url`. Like every command that touches user data they refuse a window other than `main` (the floating Now window, ADR 020). On every other OS the same names answer the typed error `unsupported`.
- **All EventKit work runs in `spawn_blocking`**, with a fresh `EKEventStore` per call. The command logic (`reminders::logic`) is written against a `RemindersStore` trait, so `cargo test --lib reminders` runs it against a fake and never touches EventKit (and so never shows a permission prompt).
- **Full access only.** `authorizationStatusForEntityType` reads the permission and never prompts; `reminders_request_access` is the only command that may show the prompt, only while the status is `notDetermined`, and nothing calls it at app start. It uses `requestFullAccessToRemindersWithCompletion:` on macOS 14 and later and `requestAccessToEntityType:completion:` below it, picked at runtime with `respondsToSelector:`. Every read and write needs `granted` (`access-denied` otherwise); `writeOnly` is reported as is and never reads.
- **Entitlement and usage string.** `src-tauri/entitlements.plist` carries `com.apple.security.personal-information.calendars`, the hardened-runtime resource entitlement that covers EventKit, Reminders included (there is no separate Reminders key; this replaces "deliberately empty" for this one key, ADR 013). `src-tauri/Info.plist` (merged into the bundle by the bundler and embedded into the debug binary by `tauri-build`) holds `NSRemindersFullAccessUsageString` (macOS 14+) and `NSRemindersUsageDescription` (older), in English, and `CFBundleLocalizations` (`en`, `de`); the German text is `resources/de.lproj/InfoPlist.strings`, copied into the bundle by `bundle.macOS.files`. macOS shows the string in the system language. The text promises exactly what slice 4 writes: it reads Reminders, shows today's on the board and sets the date when the user plans something for today.
- **Dates are components, never instants.** A due date is `{ date: "YYYY-MM-DD", time: "HH:mm" | null }` read from the year, month, day, hour and minute components as stored; nothing is converted through a time zone, so a date-only reminder never shifts by a day. `reminders_set_due` writes only year, month and day: it copies the reminder's existing `NSDateComponents` and sets those three, so hour, minute, time zone, calendar, start date and alarms stay (a reminder without a date gets a date-only component). Known and accepted: an alarm with an absolute date stays on its old day.
- **Writes are guarded, because they change data kan-do cannot restore from a backup.** Both writes are compare-and-set (`expectedDate` / `occurrenceDate` against the stored due date; `occurrenceDate` is always passed, so a retried tick of a recurring reminder cannot tick its next occurrence; else `changed` and nothing is written), check the reminder's list against the `allowedListIds` the caller passes (else `not-read`, so a list the user switched off is never written), save with `commit: true` (a failed save is rolled back), re-read the reminder (`refresh`) and answer with what the store holds (a store that kept something else is `save-failed`), and find a target state already in place as a no-op success. Ticking a recurring reminder reports the date that follows (or none when the series ended); neither is an error.
- **No create, delete, move or text edit, and no push.** The module has no function that does, and a unit test fails when its production code mentions such a call: the permission copy promises exactly that. `EKEventStoreChanged` is not used in v1; sync polls at the app's existing fetch cadence.
- **Errors are fixed typed strings** (`unsupported`, `access-denied`, `not-read`, `not-found`, `changed`, `invalid-request`, `save-failed`, `failed`), like `secrets.rs`; no platform text reaches the web view. The union is `RemindersErrorName` in `lib/reminders.ts`.
- **The web build never imports `@tauri-apps/api` for this**: `lib/reminders.ts` answers `unsupported` on the web without touching Tauri and imports `@tauri-apps/api/core` lazily.

## Consequences

- Whether macOS shows the prompt with the usage string in both languages, a signed build lists real lists, a denied permission answers `denied` and `reminders_open_settings` opens the right pane, a recurring tick behaves as in Reminders and `set_due` keeps a reminder's time and alerts is **unverified** until the user's one-time Mac check (listed in the PR of #550). An agent never grants the permission or reads real Reminders.
- A debug run (`tauri dev`) embeds the usage string, but the prompt is then attributed to the dev binary or its parent terminal (unverified, part of the same check).
- `cargo test --lib` covers the command logic and the `NSDateComponents` handling (plain Foundation, no EventKit), not the EventKit calls themselves.
- Slice 2 adds the adapter and the list roles on this contract; slice 4 the today rules and the writes.
